# Gel Chromaticity Map: codebase snapshot for agents (v1.8.0, 2026-10-09)

This project folder holds a **read-only snapshot of the source code** under `color-map-code/`, mirroring the repo layout. It is for answering questions and planning changes. The authoritative copy is the zip `gel-chromaticity-map.zip` (from the chat that built it); the built single-file app is `dist/index.html` inside that zip. Not mirrored here: `dist/` (generated), `data/*.json` (spectra and colour tables, 380 KB, generated by `tools/`), screenshots, synthetic example LEDs.

## What the app is
A static web app (one HTML file, no server) that plots 97 synthetic example colour gels, 82 artist pigments and open reflectance sets (CRI TCS 14, TM-30 CES 99, ColorChecker 24; LEE and Munsell are import-only) on CIE 1931 xy / 1976 u′v′ under any light source, with four tabs:
1. **Colour map**: filters/pigments × light source, imports, subsets.
2. **Adaptation lab**: seven chromatic adaptation transforms vs the spectral truth.
3. **LED library**: import 1000+ LED spectra, CRI/TM-30 for each, plot, filter, detail.
4. **LED compare**: swap LED A for B (same CCT/Duv, different CRI/TM-30), see how every filter/pigment shifts; TM-30 colour vector graphics.

## Where things are (read these first)
- `README.md`, `docs/ARCHITECTURE.md` (how modules fit, add a dataset/metric/CAT/tab), `docs/MATHS.md` (all formulas, CRI/TM-30 validation numbers), `docs/USER_GUIDE.md`, `docs/DATA_FORMATS.md`.
- `src/js/manifest.txt`: build order of every JS module. **All JS shares ONE global scope** (concatenated by `tools/build.py` into one `<script>`), so: function/const names must be unique across all files; top-level `const`s must be defined before any top-level code that uses them runs (order in the manifest matters); prefix per-tab names (`ld*` library tab, `cm*`/`cmp` compare tab, `lab*` lab).
- `src/js/core/`: pure colour science, no DOM. `grid-cmf.js` (380–780 nm 1 nm grid, CIE 1931 CMFs, `sums`, `chroma`), `locus.js` (CCT/Duv via Planckian table), `reference-light.js` + `cri.js` + `tm30.js` + `quality.js` (CRI, TM-30; `quality(spd)` is the one-call API).
- `src/js/led/`: `parse.js` (file formats), `library.js` (LED store, import, IndexedDB persistence, `ledReference`), `picker.js` (searchable chooser), `plots.js` (spectrum, colour vector graphic, colour ramp), `tab.js` (LED library tab, state `ld`), `compare.js` (LED compare tab, state `cmp`).
- `src/js/lab/`: adaptation lab; `lab/view.js` holds the shared `CView` canvas chart class (zoom/pan/hit-test) used by all chart tabs; `lab/sources.js` has `spdOf()`/`srcName()`, the single place that turns a source object (`{src:'bb'|'lib'|'ref'|...}`) into a spectrum; `lab/tabs.js` has `TABS` and `showTab()`.
- `src/js/app/store.js`: saved user spectra sets (IndexedDB `gelmap-sets`, `userSets`, `usSaveSoon`/`usDelete`) and the backup file (`backupBuild`/`backupRestore`, buttons `data-bk`). LEDs persist in `led/library.js` (`gel-map` DB). `loadBuiltin(kind)` shows the saved set if one exists.
- `src/js/app/`: Colour map tab, datasets registry (`registerDataset`, vocabulary tokens like `{filter}` via `tk()`), import, subset.
- `src/js/metrics/`: metric registry (`registerMetric`); `heavy:true` metrics run after first paint in slices (`runHeavy`). CRI/TM-30 are metrics.
- `src/partials/*.html`, `src/css/*.css`: markup and styles, concatenated into `src/index.html` by the build.
- `tests/`: `maths.mjs` (node; CRI/TM-30 vs colour-science fixtures, CAT identities, LED parsing), `smoke.py`, `leds.py [N]`, `pwa.py` (Playwright headless Chromium).
- `tools/`: `build.py` (build + `--check` syntax), generators for data tables and test fixtures (need `pip install colour-science`), LEE scraper.

## Build and test (in a checkout of the zip)
`python3 tools/build.py` writes `dist/`; `npm test` runs build + all four test suites; `python3 tests/leds.py 1000` is the scale test. CI: `.github/workflows/ci.yml` (not mirrored here).

## Conventions and traps for parallel work
- Add a new JS file by adding a line to `src/js/manifest.txt`; data files via `data NAME path` lines (`data?` = optional, null if missing).
- Don't give two functions the same name across files (silent override in one scope). Check with a grep before adding.
- `st` (map state), `lab`, `ld`, `cmp` are the per-tab state objects. `LED` is the library store; subscribe with `LED.listeners.push(fn)`.
- Spectra everywhere are `Float64Array(401)` on 380–780 nm at 1 nm; CRI/TM-30 sample every 5th value.
- Artifact/sandboxed hosting: no localStorage; IndexedDB persistence of LEDs silently falls back; blob downloads do not work, so exports copy to the clipboard.
- Known limits: CRI/TM-30 unreliable below ~1700 K; Rcs/Rhs checked only against an independent implementation of the same formulas; no LEE data is bundled (optional `data/lee.json`, git-ignored; see `NOTICE.md`); Munsell is import-only.
- Metrics `energyOut`/`energyAbs` (`metrics/energy.js`) feed the Colour map; LED compare computes brightness (`bright`, `stops`, `dL`) and energy (`eA`,`eB`,`dE`) per row in `cmpCompute()`, selected by `cmp.metric` and `cmp.equal`.
- `core/apparent.js` (`luvOf`, `camUcsOf`, `apparentParts`, validated in `tests/maths.mjs` against colour-science) gives the combined colour+brightness ΔE; `led/space3d.js` draws the 3D view (`c3*`) from `cmp.res.rows[].P`.
- `led/onefilter.js` (`o1*`) ranks every library light for one filter ("One filter, all lights"); it calls `cmpCtx(LA,LB)` and `cmpRowOf(X,f)` from `led/compare.js`, which `cmpCompute` also uses, so both views share one calculation.
- `led/synthetic.js` makes synthetic lights (`cmp.syn`, ids `syn:A` / `syn:B`, `synItem`, `synSpd`); `cmLight` resolves them. `led/match.js` (`m1*`) finds the filters whose colour under B is closest to a chosen filter under A.
- Example: the white-point option in LED compare (`cmpAdapter()` in `led/compare.js`): a dropdown picks none, plain u′v′ shift, the CRI von Kries (CIE 1960 u,v), the TM-30 step (CAT02, D = 1) or any matrix CAT from `lab/cat.js` with D from the advanced options. It moves B's colours (or A's, option "Move") from one light's white to the other's, so only the change in rendering remains; the source light's white maps exactly onto the target white (tested).
